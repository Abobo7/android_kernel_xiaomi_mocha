mocha Broadcom H4 character transport on Android 8.1
==================================================

The stock vendor library opens /dev/brcm_bt_drv. Android's Bluetooth HIDL
H4Protocol reads type/header/payload separately and sends type/payload with
writev. The shared Broadcom line discipline expects complete transmit packets.

RX (iteration 10): bound each copy to the requested count, retain the unread
skb tail, serialize readers, and perform user copies outside spinlocks. Empty
nonblocking reads return EAGAIN; zero-length reads return zero. Partial user
copy faults consume only the bytes actually copied.

TX (iteration 11): provide aio_write so VFS preserves the whole writev rather
than invoking write once per iovec. do_sync_write uses the same path for scalar
writes. Copy all vectors to one skb before enqueueing; return zero without
enqueueing for an empty write and discard the entire skb on a user-copy fault.
The worker drains the queue because queue_work can coalesce wakeups. A separate
packet counter is unnecessary and can race with the queue.

The queued Reset only completed after the next write. The source's one-skb
worker and VFS fallback explain that observed delay. Full syscall/logcat
evidence is kept in diagnostics/20260907-boot-fix/attempt-10-device/bluetooth-trace.

Runtime acceptance requires normal controller initialization, a valid address,
Bluetooth ON, no HCI command timeout/crash loop, and an off/on cycle. A clean
build is insufficient. Preserve the stock vendor library and recovery image.
